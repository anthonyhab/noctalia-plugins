# Hyprland 0.54 Layout Support Implementation Plan

## Overview

Hyprland 0.54 introduces per-workspace layouts (dwindle, master, scrolling, monocle). This plan outlines implementing full layout visualization, switching, and gesture support in the workspace overview plugin.

## Technical Foundation

### API Capabilities

**Reading Layout Data:**
```json
// hyprctl workspaces -j
{
  "id": 3,
  "name": "3",
  "tiledLayout": "scrolling",  // dwindle | master | scrolling | monocle
  ...
}
```

**Switching Layouts:**
```bash
hyprctl keyword workspace <id>, layout:<layout_name>
# Examples:
# hyprctl keyword workspace 3, layout:scrolling
# hyprctl keyword workspace 3, layout:master
# hyprctl keyword workspace 3, layout:dwindle
# hyprctl keyword workspace 3, layout:monocle
```

**Layout-Specific Configuration:**
- Scrolling: `direction` workspace rule (left/right/down/up)
- All layouts support per-workspace rules in hyprland.conf

## Phase 1: Layout Visualization

### 1.1 Layout Detection & Storage

**Main.qml Changes:**
- Parse `tiledLayout` from workspace objects
- Store workspace-to-layout mapping
- Expose layout info to OverviewGrid

```qml
// New property in Main.qml
property var workspaceLayouts: ({})

// Parse from workspaces data
function updateWorkspaceLayouts() {
    var layouts = {};
    for (var i = 0; i < workspaces.length; i++) {
        var ws = workspaces[i];
        layouts[ws.id] = ws.tiledLayout || "dwindle";
    }
    workspaceLayouts = layouts;
}
```

### 1.2 Layout Renderers

**OverviewGrid.qml Changes:**

Create layout-specific window positioning logic:

**Dwindle/Master (Grid-based):**
- Keep current implementation
- Windows positioned by their actual geometry
- Retiling drag-and-drop works as-is

**Scrolling Layout:**
- Horizontal or vertical tape based on `direction` rule
- Show windows as columns (horizontal) or rows (vertical)
- Indicate scroll position with visual indicators
- Window positioning:
  - Scale to fit column width (horizontal)
  - Scale to fit row height (vertical)
  - Overlap/stack for overflow indication

**Monocle Layout:**
- Show active window prominently
- Show other windows as thumbnails/tabs at edge
- Visual indicator of stack position

## Phase 2: Layout Switching

### 2.1 Layout Switcher UI

**Location:** Context menu or dropdown in workspace cell header

**Implementation:**
```qml
// Layout switcher popup
Menu {
    MenuItem { text: "Dwindle"; onTriggered: setLayout(workspaceId, "dwindle") }
    MenuItem { text: "Master"; onTriggered: setLayout(workspaceId, "master") }
    MenuItem { text: "Scrolling"; onTriggered: setLayout(workspaceId, "scrolling") }
    MenuItem { text: "Monocle"; onTriggered: setLayout(workspaceId, "monocle") }
}

function setLayout(wsId, layoutName) {
    Hyprland.dispatch("keyword workspace " + wsId + ", layout:" + layoutName);
}
```

### 2.2 Keyboard Shortcuts

- `L` key while hovering workspace: cycle through layouts
- `Shift+L`: cycle backwards
- Numeric shortcuts: 1=dwindle, 2=master, 3=scrolling, 4=monocle

## Phase 3: Layout-Appropriate Gestures

### 3.1 Drag Behaviors

| Layout | Drag Action | Implementation |
|--------|-------------|----------------|
| **Dwindle** | Retile split (current) | Keep existing `calculateRetileTarget` |
| **Master** | Swap master/stack | Detect drop zone (master vs stack area) |
| **Scrolling** | Reorder columns | Track column position, dispatch reorder commands |
| **Monocle** | Cycle stack | Drag up/down to change stack position |

### 3.2 Scroll/Wheel Behaviors

| Layout | Wheel Action | Implementation |
|--------|--------------|----------------|
| **All** | Navigate workspaces | Keep existing behavior |
| **Scrolling** | Scroll columns | Horizontal scroll for horizontal layout |
| **Monocle** | Cycle windows | Use `layoutmsg cyclenext` / `cycleprev` |

### 3.3 Double-Click Actions

| Layout | Action | Command |
|--------|--------|---------|
| **Dwindle** | Toggle floating | `togglefloating` |
| **Master** | Toggle master | `layoutmsg swapwithmaster` |
| **Scrolling** | Focus/maximize column | `focuswindow` on column |
| **Monocle** | Toggle floating | `togglefloating` |

## Phase 4: Persistence & Integration

### 4.1 Remember User Layouts

Store workspace layout assignments in plugin settings:

```json
// settings.json
{
  "workspaceLayouts": {
    "1": "dwindle",
    "2": "master",
    "3": "scrolling"
  }
}
```

### 4.2 Apply on Launch

When shell starts:
1. Read saved layout assignments
2. Apply via `hyprctl keyword workspace`
3. Respect user's hyprland.conf workspace rules (don't override if explicitly set)

```qml
// On plugin load
Component.onCompleted: {
    applySavedLayouts();
}

function applySavedLayouts() {
    var saved = getSetting("workspaceLayouts", {});
    for (var wsId in saved) {
        Hyprland.dispatch("keyword workspace " + wsId + ", layout:" + saved[wsId]);
    }
}
```

### 4.3 Settings UI Integration

Add to Settings.qml:
- "Remember workspace layouts" toggle
- "Apply layouts on startup" toggle
- Layout assignment table/grid for manual configuration

## Key Decisions Needed

1. **Scrolling Direction Detection:** Should we read the workspace rule `direction` to show horizontal vs vertical scrolling layout?

2. **Monocle Stack Visualization:** Show all windows as thumbnails at top/bottom, or just indicate stack position numerically?

3. **Layout Persistence Scope:** Remember layouts for all workspaces, or only ones user explicitly changed via overview?

4. **Gesture Priority:** Should we implement Phase 3 (gestures) before or after Phase 1.2 (visual rendering)?

5. **Backward Compatibility:** How to handle Hyprland versions < 0.54 that don't have `tiledLayout` field? (Graceful fallback to dwindle/master detection)
